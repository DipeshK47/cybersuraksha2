रेवा काल्पनिक मरम्मत folder में बदले नाम वाली टिकट file पाती है। निखिल बदली शेयरिंग setting भी देखता है। वे ऐसे अंदाज़े वाले सुधारों के बजाय सामान्य edit रोकते हैं जो बदलाव के काम के सबूत मिटा सकते हैं।

डायरी में file नाम, समय और permission बदलाव हैं, पर करने वाले की पहचान नहीं है। रेवा देखी बातें लिखकर कारण अनजान रखती है। संदेह वाला pattern report का आधार हो सकता है, किसी खास आरोप का सबूत नहीं।

वे स्कूल के जाने-पहचाने रास्ते से teacher को बताते और दिए बदलाव डिटेल्स बचाते हैं। teacher आगे शेयरिंग सीमित करने की स्कूल प्रक्रिया अपनाते हैं। विद्यार्थी folder नहीं मिटाते, शक वाले साथी से भिड़ते नहीं और प्रभावित account पर प्रयोग नहीं करते।

निखिल तारीख अच्छी लगने पर सबसे नया backup चुनता है। रेवा जाँची पुरानी copy को खराब संस्करण से मिलाती है। नया होना सही recovery समय नहीं बताता; record काम का और तय टिकट लिस्ट से मेल होना चाहिए।

teacher चुना backup अलग test जगह खोलते हैं। सामान्य काम लौटने से पहले तय file खुलना, टिकट गिनती मिलना और सीमित access जाँचा जाता है। team बाद के गायब edit review के लिए लिखती है, सब कुछ होने का दावा नहीं करती।

recovery record में देखी बात, इंसिडेंट रोकना और परखी वापसी अलग रखें। backup कार्ड लेकर एक अनसुलझा मुद्दा बताएँ। पढ़ने योग्य record लौटना पहले copy लिए जाने का जवाब नहीं देता, न teacher की इंसिडेंट review की जगह लेता है।
